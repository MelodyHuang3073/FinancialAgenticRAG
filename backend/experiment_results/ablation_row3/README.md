## 與其他組的一致性檢查

- 先跑 `grading_check.py`:本列標籤格式與依據列通過。
- 再把本列的答案與其他 11 組(基準、疊加第 0 到 4 步、兩個 Gemini、列 1、2a、2b)比:挑出「答案內容看起來相同(同樣答找不到,或數字集合高度重疊)但標籤不同」的 29 筆(題目與組別的配對,共 18 題),逐一把答案並排讀完。結果:15 題的差別來自答案本身不同(例如他組答 No、本列答 Yes,或他組數字正確、本列錯),標籤合理;1 題改標籤:獨立測試集 34(J&J 總負債)本列答案與疊加第 2 步逐字相同,第 2 步判 S(依據列 4),本列由 C 改為 S;另 2 題(獨立測試集 70、103)的差別是其他組之間本來就不一致,2026-11-11 已跨組統一,見下一項。
- 2026-11-11 把發現的三題跨組統一(各組 README 與標籤同步更新):
  - 獨立測試集 34(J&J 總負債):寫出「30.9%」(用四捨五入的 $47.9B、$36.6B 算,標準答案 30.8%)一律判 S(第 4 列),列 2b 由 C 改 S;沒寫百分比或寫「約 31%」判 C。

## 用量

300 題:答案生成 300 次,**沒有拆題器呼叫**(基準 234 次、列 2a 471 次、列 2b 171 次);合計 3,718,830 token(輸入 3,377,121、輸出 341,709),每題約 12,396。每題耗時平均 14.6 秒、中位 13.6、最慢 36.1。基準是 4,936,782 token(每題 16,456、平均 20.2 秒)。沒有拆題器,證據也只用單一查詢,所以 token 與耗時都比基準少。
