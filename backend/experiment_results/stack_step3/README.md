# 疊加第 3 步:+ C4 拆題器與公式庫(單檔 300 題)

疊加實驗的第 3 步(2026-11-08 修訂版規劃,見上一層的 [EXPERIMENT_PLAN.md](../EXPERIMENT_PLAN.md)),評分規則在其第 9 節。

## 這一步的設定

在第 2 步之上只加拆題器與公式庫(C4),沒有加任何完整系統沒有的東西。

| 項目 | 內容 |
|---|---|
| 日期 | 2026-11-09 |
| 程式 | `backend/stack_runner/run_step.py --step 3`(本分支,「疊加實驗第 3 步程式」的 commit),4 個程序同時跑(兩個題組各切 2 份),先冒煙測試 2 題 |
| 模型 | gpt-5-mini;作答一次呼叫兩則訊息(系統訊息、使用者訊息),不設任何其他參數;拆題器另有自己的模型呼叫 |
| 規劃 | 系統自己的規劃器:題型判斷 → 公司對齊到財報 → 查公式庫 → 趨勢題補前一年 → `_plan_queries`。命中公式庫的題(129 題)每個公式變數一條查詢,不呼叫模型;沒命中的算數題由模型拆子問句,加問題原文與「在財報哪個章節」的主題查詢;說明題用分類器的查詢句加公式或主題查詢 |
| 檢索 | 所有不重複的查詢依規劃順序串成**一個**字串給 `rank_bm25`,取 16 筆(仍是步驟 1 的檢索,不是系統檢索器:沒有加權、配額、視窗 30) |
| 提示詞 | 與第 2 步完全相同(由系統的 `generate_answer` 組成,含兩行路由文字,沒有 Computed value 與 Verification summary) |
| 檢查 | 300 題齊全,0 次錯誤,沒有空答案,合併檢查通過;拆題器 234 次呼叫全部成功,沒有退回規則式;離線驗證:規劃的查詢 0 個漏搜、0 個多搜(除問題原文本身)、第 1 與 2 步的 600 筆提示詞逐字不變 |
| 評分 | 依規劃第 9 節逐題讀完 300 題答案,對標準答案評分,非 C 的標籤記依據(決策表列號),通過 `grading_check.py`,與第 0 到 2 步及基準跨組比對,另做機械篩選(C 的答案要含標準答案的主要數字、非 C 的答案不得已含全部標準答案數字) |

規劃的來源統計(`summary.json` 的 `decompose_source`):只用公式 104 題、公式加主題查詢 8 題、模型拆題加問題原文 66 題、模型拆題加主題查詢加問題原文 55 題、只剩分類器的查詢 67 題。拆題器輸入 token 共 95,915,和基準的拆題器完全相同(基準也是 234 次呼叫、同一批題)。

## 跨組比對(規劃 9.6)

- 與第 2 步:標籤相同 229 題;與第 1 步:223 題;與第 0 步:196 題;與基準:268 題。
- 基準非 C、這一步 C 的有 8 題(訓練集 61、135,獨立測試集 10、12、33、50、89、104);基準 C、這一步非 C 的有 24 題。
- 機械篩選:C 的 24 題標準答案主要數字不在答案裡,逐題重讀,都是單位換算(1.8bn 對 1,824)、文字型標準答案或答案給了標準答案的等值寫法;非 C 的 2 題答案含全部標準答案數字(訓練集 96、獨立測試集 24),逐題重讀後,訓練集 96 同時給了 $82.31 與標準答案 $66.56(改判 P,第 20 列),獨立測試集 24 的 15.1% 對 15.0% 維持 S。
