# 消融實驗的比較基準(單檔 300 題)

之後每個消融實驗都跟這份基準比。

## 內容

- 完整系統(dev 的程式碼,所有消融開關關閉),300 題(訓練集 150、獨立測試集 150),**每題只載入它自己的那份財報**(老師的標準:一份檔案加正確答案就算對),每題只跑一次。
- 跑的日期:2026-10-26。模型 gpt-5-mini。解析快取是 10/20 建的 `original_corpus_cache.pkl`、`outsample_corpus_cache.pkl`。
- 判分:由 AI 助理(Claude)依固定規則逐題閱讀答案,對照標準答案標 C/S/P/W,作者複核並更正(例如 Amazon 成長率 12.0% 原標錯誤,經作者指出改為正確;2026-10-28 複核見下);自動評分只當初篩。沒有獨立的第二位評審。判分規則見第四章簡報 4.1。

標籤:C 正確、S 小誤差(結論對,百分比差 0.1 個百分點)、P 部分正確、W 錯誤。財報自己印的整數百分比(例如 Amazon 成長 12%,標準答案 12.4%)算 C;寫成「12.0%」這種四捨五入後一樣的寫法也算 C(2026-10-27 更正:原本標 W)。標準答案本身有疑慮的題(Boeing 有效稅率、AWW 股利)照財報判斷。

## 判分複核(2026-10-28、10-29)

判分規則整理成書面後(第四章簡報 4.1 的三頁),用同一套規則把基準與三個消融的答案重新判一次:

- **規則的實際做法**:答案裡的數字,要是依財報金額算出值的正確四捨五入;差 0.1 個百分點算 S。標準答案本身有尾差時以財報算出值為準(例如 CVS 營收成長 7.8%,算出 7.848%,標準答案寫 7.9%,仍算 C)。科目或對象不同算 P。
- **淨利口徑**(10-29 新增):題目只寫 net income / net earnings、沒指定口徑時,含非控制權益的淨利與歸屬於公司的淨利都算合法的行;答案有寫明用哪一行、金額差在 1% 內、結論與主因對,就算 C(例如 PepsiCo、Amcor、CVS、General Mills 的獨立測試集題)。訓練集沒有這種題。
- **基準**:300 題全部用書面標準逐題讀過。被改的標籤只有 1 個:獨立測試集 24 題(Amazon 產品與服務銷售成長)的服務銷售成長答 15.1%,依財報金額算出 15.045%,應寫 15.0%,C 改 S。當時基準是 289 / 2 / 5 / 4;11-01 的一致性複核又改了 1 個標籤,現在是 290 / 1 / 5 / 4,答對率 96.7%(見下一節)。其餘邊界題維持 C:Amcor 毛利率降幅(兩個財報印的百分比相減)、PayPal 營運資金(標準答案進位有誤)、整數百分比的四捨五入、Corning 說明題(答案有指出營業利益翻倍)。
- **三個消融**:各實驗的 300 題答案都用同一套規則逐題讀過(沒有用程式比對代替閱讀)。改了 13 個標籤(沒有領域知識 6、沒有 PoT 4、拿掉題型分類器 3),見各分支 `experiment_results/*/README.md`。

## 一致性複核(2026-11-01)

把基準、6 個消融實驗與 4 個換模型實驗(共 11 組標籤)放在一起,跨組檢查同一題相近的答案是否得到同一個標籤,發現少數格子套用規則不一致,全部依下面的書面規則統一(各分支的 `experiment_results/*/README.md` 與 `build_comparison.py` 同步更新)。

**判分規則(最後版本)**

1. 題目指定四捨五入位數時(例如「Round to one decimal place」),答案必須是依財報金額算出值的正確四捨五入;差最後一位(例如 54.2% 對 54.1%、$4.15 對 $4.14)算 S;輸入對但差兩位以上算 P(2026-11-04 補充,見下一節);輸入對但算式結果大幅算錯算 W。
2. 題目沒有指定位數時(成長率),答案寫財報自己印的整數百分比,或把正確值取較粗的位數,都算 C(例如 Amazon 成長 12%、標準答案 12.4%)。
3. 題目只給比率公式、沒有要求百分比時,0.33 與 33.28% 都算 C(Microsoft ROE);答案若又附一個錯誤的百分比(33.31%、33.00%)算 S。
4. 原因題只要答案把標準答案的主因列為原因之一就算 C(不要求排第一);完全沒有提到主因算 P 或 W;答「無法判斷」算 W。
5. 列舉題:答對至少一項算 P,全部答對算 C,一項都沒有算 W。
6. 淨利口徑、科目或對象不同的規則維持 10-29 的版本(見上一節)。

**基準被改的 1 格**:獨立測試集 8 題(Microsoft ROE)答 0.33,題目沒要求百分比,由 S 改 C。基準因此是 290 / 1 / 5 / 4(訓練集 149 / 0 / 0 / 1,獨立測試集 141 / 1 / 5 / 3)。

**各組被改的格子**(格子 = 一組的一題;只列標籤實際改變的)

| 組別 | 改了什麼 |
|---|---|
| 題型分類器全走數值路徑 | Microsoft ROE 小誤差改正確;PayPal 營運資金(訓練集 119)正確改小誤差 |
| 沒有領域知識 | PepsiCo 淨利下降原因(獨立測試集 11)部分改正確 |
| 沒有檢索加權 | PepsiCo 毛利率 54.2%、Nike 淨利降幅 43.6% 正確改小誤差 |
| 沒有驗證與重試 | Amazon 成長 12%、AmEx 營收成長 10%、Microsoft ROE 0.33 小誤差改正確;MGM 淨利降幅 72.5% 正確改小誤差 |
| Gemini 3.5 Flash-Lite | J&J 淨利翻倍主因(獨立測試集 33)部分改錯誤 |
| Gemini 3.1 Flash-Lite | Microsoft ROE 小誤差改正確;MGM 每股盈餘(獨立測試集 105)部分改小誤差 |
| gpt-5-nano | PepsiCo 毛利率、Nike 淨利降幅正確改小誤差;J&J 淨利翻倍主因部分改錯誤 |

檢查方法:(1)標準答案是百分比或單一數字的題(約 90 題),把答案的主要數字對照標準答案,依「完全一樣、差一個最後一位、財報印的整數」分類,逐格檢查各組標籤;(2)原因題、列舉題、判斷題共 210 題中,各組標籤不全相同的 93 題,逐題讀過所有組的答案;(3)是非題的結論與標籤逐格比對。(1)(2)(3)沒有發現其他不一致;各組標籤完全相同的題沒有重讀。

## 限制

- 單次執行。同一題重跑可能不同(10/25、10/26 對獨立測試集 19 題各跑一次,有 5 題結果不一樣),所以這份基準的數字有約 1% 以內的波動;消融結果要用同樣的跑法(單檔、一次)比較,差距在波動範圍內不下結論。
- 判分時每題先讀答案開頭約 230 字,有疑問的 13 題再讀全文;沒有逐字讀完全部 300 個答案(這是判分當時的做法,沒有保存逐題的閱讀紀錄)。
- 訓練集是開發集,領域知識與規則是用它調的,獨立測試集的結果比較能代表沒看過的題目。

## 後續消融怎麼跑

1. 在新分支加環境變數開關(預設關閉、行為不變),只關一個元件。
2. 單檔跑全部 300 題,可切成多份並行(需要在 Windows 用 PowerShell `Start-Process` 背景執行,先看 `python -m app.agent.usage_tracker` 的額度,300 題約 450 萬 token、約 40 到 60 分鐘):
   `python tests/run_single_file_subset.py --set train --candidates experiment_results/all_candidates_train.json --out <輸出檔> --shard 0/2`
   (`--shard 1/2`,獨立測試集把 `train` 換成 `out`)。
3. 合併分片輸出,確認 300 題不缺、沒有 `error`。
4. 逐題讀答案,跟 `baseline_standard.json` 同題比較,標 C/S/P/W。
5. 注意跑的程序是否中途死掉(曾因檔名比對失敗停掉一份分片)。
