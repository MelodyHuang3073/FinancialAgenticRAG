# 疊加第 4 步:+ C5 系統檢索器(單檔 300 題)

疊加實驗的第 4 步(2026-11-08 修訂版規劃,見上一層的 [EXPERIMENT_PLAN.md](../EXPERIMENT_PLAN.md)),評分規則在其第 9 節。這一份是 2026-11-22 在目前的獨立測試集與訓練集重跑的版本。

## 這一步的設定

在第 3 步之上只換檢索器(C5),沒有加任何完整系統沒有的東西。

| 項目 | 內容 |
|---|---|
| 日期 | 2026-11-22 |
| 程式 | `backend/stack_runner/run_step.py --step 4`(本分支,「疊加實驗第 4 步程式」的 commit),4 個程序同時跑 |
| 模型 | gpt-5-mini;作答一次呼叫兩則訊息(系統訊息、使用者訊息),不設任何其他參數;規劃器另有自己的模型呼叫 |
| 規劃 | 與第 3 步相同(系統的規劃器:題型判斷、公司對齊、公式庫、趨勢題補前一年、`_plan_queries`);規劃來源的統計與第 3 步逐項相同 |
| 檢索 | 由系統的 orchestrator 自己跑第一輪:規劃出的每個查詢各搜一次(一般 top 5、敘述 top 15)、8 條加權、排除已取過的、跳過已有的(指標、年度)、每個查詢以自己的文字重算報表類型提示,再依配額選進視窗(最多 30 筆);作答呼叫再取 16 筆。PoT 與驗證關閉,不重試 |
| 提示詞 | 與第 3 步完全相同(由系統的 `generate_answer` 組成,含兩行路由文字,沒有 Computed value 與 Verification summary);改變的只有放進去的證據 |
| 跑法 | 訓練集 150 題與獨立測試集 150 題分兩階段、各 4 個程序依序執行,用量與耗時分開記錄(時間窗在 `run_windows.json`);先跑離線測試 35 項,沒有另外做 2 題冒煙測試(程式與提示詞和上一次執行相同,沒有改動) |
| 檢查 | 300 題齊全,0 次錯誤,沒有空答案,合併檢查通過;規劃器 258 次呼叫(訓練集 123、獨立測試集 135,與第 3 步相同) |
| 評分 | 依規劃第 9 節逐題讀完 300 題答案,對標準答案評分,非 C 的標籤記依據(決策表列號或第 9.4 節規則),通過 `grading_check.py`,並與第 0 到 3 步、比較基準、兩個 Gemini 跨組比對 |
