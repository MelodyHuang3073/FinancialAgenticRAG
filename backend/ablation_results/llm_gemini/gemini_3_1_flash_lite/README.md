# 換模型實驗:Gemini 3.1 Flash-Lite(對照 gpt-5-mini)

- 跑法:完整系統,只把產生答案與拆題的 LLM 換成 `gemini-3.1-flash-lite`(Google 免費額度金鑰),單檔、300 題各跑一次,2026-10-29;程式碼是這個分支(`app/agent/gemini_call.py` 的重試與系統指令,其餘管線與基準相同)。
- 比較對象:`../../baseline/baseline_standard.json`(同樣的單檔 300 題、完整系統、gpt-5-mini)。
- 判分:由 AI 助理(Claude)依固定規則讀答案對照標準答案、作者複核並更正,標 C 正確 / S 小誤差 / P 部分正確 / W 錯誤,規則與基準、三個消融完全相同(見 `../../baseline/README.md`)。300 題每題都讀過,沒有用程式比對代替閱讀。注意出題與判分都是 Claude,測 Claude 系列模型時可能有偏向,論文裡要註明。

**變差的題(基準 C、這次非 C)24 題**:訓練集 13 題、獨立測試集 11 題(含獨立測試集 33 題由 P 變 W),原因依 `note` 歸納:
- 結論相反:3M 速動比率答 Yes、Adobe 自由現金流轉換率答 No、CVS 是否資本密集答 No、Best Buy 毛利率是否穩定答 No(其實最大波動 1.1 個百分點)。

單次執行,同一題重跑可能不同(基準對 19 題各跑三次有 6 題結果不一致),差在幾題以內不能下結論。

## 備援答案與補跑(必讀)

免費額度每個模型每天約 500 次請求(每分鐘 15 次),一次 300 題需要約 900 次,同一天跑不完。額度用完之後,LLM 呼叫會失敗,系統不會報錯,而是退回「不經 LLM」的備援輸出(直接列出證據、或列出計算結果)。這是 API 失敗,不是模型答錯,所以這些題不拿來判分,等額度重置後補跑,判的是補跑後的答案。

- 第一次跑完時有 35 題是備援輸出(訓練集 116–150 題偶數題、獨立測試集 122–150 題),額度在跑到後段時用完。
- 補跑分成四輪才補齊:前兩輪遇到額度尚未恢復,仍有一部分題再度回備援輸出;第三輪起才全部成功。其中有一種備援輸出(開頭為 “Analysis based on retrieved financial evidence”)一開始沒被辨識出來,混進了「已完成」的題目,直到逐題讀答案時才發現並重跑;300 題中現在沒有任何一題是備援輸出。
- 補跑的 35 題:31 題 C、2 題 P、2 題 W。


- 2026-10-29 補查:除了「答案是備援輸出」,還檢查了拆題的 LLM 呼叫是否悄悄失敗(失敗時系統退回規則式拆題,答案看起來正常)。做法:用用量紀錄(只記成功的呼叫)與分類器預期的呼叫次數逐題對照,四個分片都對得上,只有獨立測試集 140 題少一次拆題呼叫;另有訓練集 116 題的答案來自較早、額度尚不穩定時的補跑。這兩題重跑後答案與標籤都不變(C)。其餘題沒有發現遺漏。
